#### 🛡️ Core Concurrency Invariant: Pessimistic Row Lock & Idempotency Check

```java
@Transactional
public BookingResponse processConcurrentBooking(BookingRequest request) {
    // 1. Guard against concurrent overbooking using DB-level pessimistic write lock
    Seat seat = seatRepository.findByIdWithPessimisticLock(request.getSeatId())
        .orElseThrow(() -> new ResourceNotFoundException("Seat not found"));

    if (seat.getStatus() != SeatStatus.AVAILABLE) {
        throw new ConflictException("Seat already reserved by another transaction");
    }

    // 2. Lock seat & commit transactional state change
    seat.setStatus(SeatStatus.LOCKED);
    seatRepository.save(seat);

    // 3. Emit asynchronous event to Kafka topic for decoupled notifications
    kafkaTemplate.send("booking-created-topic", new BookingCreatedEvent(request.getUserId(), seat.getId()));
    
    return new BookingResponse(seat.getId(), "RESERVED_SUCCESSFULLY");
}
```
